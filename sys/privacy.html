Privacy Policy

Last updated: 9 November 2026

Sys is a personal, local-first academic information organizer. This policy explains what it accesses, why, where data is stored, and how users can remove access.

1. Controller and scope

Sys is an independent personal project operated by its developer. Privacy contact: pedrocarrola2006@gmail.com. This policy covers the Sys desktop application and this informational website. Sys is not affiliated with Google or Instituto Superior Técnico.

2. Information accessed

  • IST Fénix: permitted academic profile information, course information, class schedules, assessment dates and academic results, using read-only API access.
  • Gmail (after account authorization): the authorized account address, message and thread identifiers, subjects, sender and recipient headers, timestamps, labels, message text, snippets and attachment metadata (such as filename and size). The first version excludes messages in Spam and Trash and does not download attachment file contents.
  • Google Calendar and Google Drive: not active in the current release. Any future integration will request its own appropriate read-only permission before accessing events or files. Shared files will be available only insofar as the authorized account itself has access.

Access to one Google account does not give Sys access to another account. Each Google identity must authorize separately.

3. Why this information is used

Data is retrieved, synchronized, organized and indexed to support the user's personal academic planning, mailbox reference and local search. It is not used for advertising, marketing, credit scoring, profiling for third parties or training generalized AI models.

4. Google OAuth permissions

The Gmail integration requests https://www.googleapis.com/auth/gmail.readonly. It allows reading email but not sending, modifying, labelling or deleting messages. Other Google permissions are not requested by the current Gmail authorization. Access is only activated after the user chooses a Google account and grants consent on Google's authorization screen.

5. Storage and retention

In the current version, email text and metadata are stored in a SQLite database on the user's Windows device; Google OAuth access and refresh tokens and the Desktop client secret are stored through Windows Credential Manager. Academic records are also held locally. No message content or OAuth token is committed to the application's GitHub repository or placed on this website.

Locally synchronized records remain until the user removes them or deletes the local database; they are not automatically deleted when Google access is revoked. The SQLite file itself is not automatically encrypted by Sys, so users should protect their Windows account, device and backups.

6. Transfers, sharing and this website

Sys accesses Google data through Google's API directly from the user's computer. The current version does not upload synchronized Google content to a Sys-operated cloud server, advertising network or external AI service. The application does not sell or disclose Google user data to data brokers or advertisers. If future functionality involves disclosure to an external service, this policy and the consent flow must be updated before that processing is enabled.

This public informational site does not contain user inboxes or academic data and uses no analytics scripts, advertising pixels, cookies set by Sys or sign-in forms. GitHub Pages, the website host, may process visitor network metadata under GitHub's privacy statement.

7. Revocation, access and deletion

Users can stop synchronizing an account and revoke Google's authorization at Google Account → Third-party access. Revoking tokens does not erase copies already stored on the computer. To remove local Google data, the owner must delete the corresponding local stored records and credentials. Contact the developer for help with local deletion. There is no cloud-hosted Sys account or hosted copy of the user's mailbox to delete.

8. Google Limited Use commitment

Sys's use and transfer of information received from Google Workspace APIs will adhere to the Google Workspace API User Data and Developer Policy, including the Limited Use requirements. Google user data is not sold, used for advertising, or used to train generalized or foundation AI models.

9. Changes and contact

Material changes to sources, permissions, data handling or external processing will be reflected in this policy before release. For privacy questions or deletion requests, email pedrocarrola2006@gmail.com.
